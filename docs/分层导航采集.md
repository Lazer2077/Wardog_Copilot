# 分层导航采集 v2

本次补齐局部规划接口、接收局部计划的规则建议器和只读采集器。采集时由人驾驶，软件不构造键盘执行器、不发送按键。现有在线 Autopilot 的控制链暂未替换；视觉避障模型和真正的自动/人工控制权切换尚未接入。

## 开始下一次采集

双击项目根目录 `KODIAK导航采集.cmd`，或运行：

```powershell
python -m wardog_ad collect --vehicle KODIAK --camera-view unknown --fps 15 --max-width 512
```

1. 退出其他自动驾驶程序，确认正在驾驶 KODIAK。在采集面板确认第一/第三视角。
2. 战术地图自动显示在采集面板左侧，无需点击打开。默认跟随识别到的当前地图，显示当前位置、完整参考路线、局部路线和目的地。已有目标自动显示；需要修改时在地图上左键点选，可勾选固定地图以关闭自动切图。目标按地图分别保存，修改时会暂停采集。
3. 回到游戏。地图持续显示，查看地图不会暂停采集。暂停时也会预览定位、路线和速度，但不保存视频。必要时先手动缓行数米以估算朝向和速度，观察面板状态。手动选择底图后暂时停止跟随，勾选“跟随当前地图”可恢复。
4. 按 **F10** 开始记录，沿导航路线手动驾驶。可以先采多个 3–5 分钟的独立会话，分别覆盖左转、右转、停车和绕障，避免只重复直行。
5. 需要示范纠偏时按 **F8** 开始标记，完成后再按 **F8** 结束。默认原因是避障，也可在面板选择路线纠偏、定位错误、紧急停车或其他。**F7** 记一次障碍事件，**F9** 记一次碰撞事件。
6. 按 **F12** 结束保存，随后执行 `python -m wardog_ad dataset-check data/driving/会话目录`，检查 `hierarchical_coverage` 和告警。

F8 在采集器中只标记示范段，不启动自动驾驶。全程人工驾驶下，这些事件不等同于真实自动驾驶接管。发生碰撞请保留并标记，不要把它默认为成功绕障。

F11 切换视角标签；按 C 后标签变为未知，需要重新确认。ESC、M、I、TAB、F、0 会保守地暂停采集，关闭菜单/回到驾驶位后按 F10 恢复。物品界面仍需采后检查，不能保证所有游戏菜单都有对应热键。

也可预先指定目标：

```powershell
python -m wardog_ad collect --vehicle KODIAK --camera-view first_person --map zestafona --to 1000,1000
```

以上坐标仅是语法示例，不是推荐路线。默认是地图像素坐标；`--game` 将 `--to` 解释为游戏坐标。显式 `--map` 固定本次采集地图。通过面板固定地图会同时保存该设置。

## 局部规划接口

`wardog_ad/local_planner.py` 定义：

- `LocalPlanner.plan(path, state, progress_px, route_id, now, perception)`：返回统一 `LocalPlan`。
- `ReferenceLocalPlanner`：在全局路线前方采样约 60 米、5 米间隔的局部参考，生成前视目标和曲率/终点约束下的速度。
- `LocalPlanRuleController.step(state, plan, now)`：使用计划中的局部目标和目标速度，计算纯跟踪几何转向、横摆反馈和 P 速度控制建议。它不维护 PI 积分或自动脱困历史，适用于人工驾驶时的确定性对照。
- `PerceptionContext`：为后续视觉模块预留障碍检查时间和阻塞状态；已知新鲜阻塞时要求停车、请求重新规划。它还不是视觉检测器。

名义局部计划的 `trajectory_*` 目前是参考路线的副本，**不是人工避障轨迹或专家标签**。始终明确记录 `obstacle_checked=false`、`execution_approved=false`；没有把地图道路当作已经确认无障碍。未来视觉局部规划器可通过相同接口替换该实现。

地图坐标单位为像素。新字段 `reference_ego_m`、`trajectory_ego_m`、`target_ego_m` 都是 **[右向米, 前向米]**。旧 `navigation.local_target_m` 为兼容 TCP 保留 **[右向米, 负前向米]**，同时记录其坐标约定，训练时不要混用。

## 文件及标签

`manifest.json` 的 `schema_version=2`，保留车型、视角、控制与标注语义、采集配置和完整性状态。

| 文件 | 内容 |
|---|---|
| `video_*.avi` | 默认最大宽度 512 的画面，保留宽高比，采集器面板区域被遮罩 |
| `routes.jsonl` | 每条完整全局参考路线的 `route_id`、地图、目标、平滑后点列、原始点列和米/像素比例 |
| `navigation.jsonl` | 定位及置信度、速度来源、全局路线引用、局部计划、规则建议、源图像时间/帧 ID、处理完成时间和延迟 |
| `frames.jsonl` | 每帧真实时间、实际观测按键、视角、车型、最新可用导航快照、人工纠偏状态及有效标志 |
| `events.jsonl` | 按键变化、暂停/失焦、目标修改、纠偏起止、障碍/碰撞事件、丢帧和错误 |

规则建议为 `navigation.rule_control`，包含连续 `steer/throttle` 轴值、目标速度、控制器版本、模式和计算信息；`applied=false`。它不是实际发送的 WASD，不是人工示范的真值。正转向表示向右，正 throttle 表示向前；负 throttle 的驾驶含义依赖速度，不能简单理解为永远刹车。

每帧 `intervention` 包含 active、episode_id、reason、started_t、标注来源和 `actual_control_source=manual`。关闭会话时若纠偏段仍活跃，会自动记录结束原因 `session_closed_not_human_success`，不会默认为人工确认成功。

## 时间与有效性

统一采用会话相对单调时钟，包括嵌套 fix 时间。录像 AVI 标称 FPS 不能代替实际帧时间。当前画面使用的是**采集开始前已完成**的最新导航结果；因此导航可能有延迟，不应把它的 pose 当成当前画面的精确真值。保留 navigation_id、源 frame_id、源时间、processed_t、processing_latency_s 和每帧 navigation_age_s，便于后续对齐。

暂停预览的导航没有保存图像，`frame_id=null`，但有独立导航 ID 和时间。编码器丢帧时，导航源帧也可能没有对应视频索引，丢帧事件会保留。训练不可盲目按帧 ID 连续性连接。

视角、车型、暂停、失焦或目的地变化都会切换 `context_id`，清掉旧建议，重置时序估计。旧任务即使计算完成也不能发布到新上下文。帧内同时记录：

- `training_candidate`：基本图像/按键/车型/视角条件通过。
- `label_validity.reference_route_valid/local_plan_valid/rule_control_valid`：检查时效、上下文、视角、地图与路线 ID 是否一致。
- `hierarchical_training_candidate`：基本条件和局部计划、规则建议均可用；仍须人工审核，并不表示驾驶示范无碰撞。

`dataset-check` 会报告完整路线数、各类标签覆盖帧数和标记事件数。零分层候选会给出告警，即使录像文件本身完整。

后续轨迹学习需要从实际定位序列构造人工未来轨迹，检查定位误差、导航延迟、菜单、碰撞及跨会话/视角边界；未来轨迹只能作为监督目标。现有 `imitation.py` 仍是旧的离线按键基线，不能直接当作已经训练好的分层局部规划模型。
